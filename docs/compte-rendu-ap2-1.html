AP2.1 — Configuration d'un serveur Windows et du service DHCP

Compte rendu des travaux effectués dans le cadre de la mission de découpage du réseau M2L : adressage IPv4, installation de DHCP sous Windows Server, création d'une étendue et tests de connectivité.

Windows Server 2022PowerShellDHCPTests réseau

Ce document reprend les cinq pages du compte rendu AP2.1 transmis. Il décrit la partie serveur Windows et DHCP de l'atelier. Il ne démontre pas à lui seul la configuration des VLAN, des commutateurs Cisco ou du serveur Debian prévue par le sujet général.

1. Configuration de l'adressage IPv4 fixe

Sur un serveur Windows Server 2022 installé sans interface graphique, j'ai utilisé l'outil sconfig pour choisir la carte réseau et définir une adresse IP statique.

ParamètreValeur indiquée dans le compte rendu
Adresse IPv4 du serveur192.168.20.2
Passerelle par défaut192.168.20.1
Serveur DNS utilisé dans ce test8.8.8.8
Nom d'hôteSRV

Le nom de l'ordinateur a ensuite été modifié dans sconfig pour devenir SRV. Les captures et le texte d'origine présentent de légères différences dans les paramètres affichés ; les valeurs ci-dessus sont celles décrites dans le texte.

2. Installation du rôle DHCP

Le rôle DHCP et ses outils d'administration ont été installés dans PowerShell avec la commande :

Install-WindowsFeature DHCP -IncludeManagementTools

Ce rôle permet de distribuer automatiquement les adresses IPv4 aux postes clients, notamment à ceux du sous-réseau CURLING cité dans le document.

3. Démarrage et vérification du service DHCP

Après l'installation, le service a été démarré puis vérifié avec les commandes suivantes :

Start-Service DHCPServer
Get-Service DHCPServer

Dans la capture du compte rendu, Get-Service DHCPServer affiche Running, ce qui confirme que le service est démarré.

4. Création de l'étendue CURLING

J'ai utilisé la commande PowerShell Add-DhcpServerv4Scope pour créer une étendue d'adresses à distribuer aux clients du sous-réseau CURLING, puis Get-DhcpServerv4Scope pour contrôler sa configuration.

Add-DhcpServerv4Scope
Get-DhcpServerv4Scope

Le compte rendu mentionne une plage initialement souhaitée de 192.168.20.10 à 192.168.20.100. Le résultat affiché dans la capture se termine toutefois à 192.168.20.120. Cette divergence est conservée telle quelle : le compte rendu ne permet pas de confirmer qu'elle a été corrigée.

5. Test de communication avec le serveur

Depuis un poste client, la commande ping vers le serveur 192.168.20.2 a d'abord échoué. Une règle a ensuite été ajoutée au pare-feu Windows pour autoriser les requêtes ICMPv4 entrantes.

Une nouvelle tentative de ping a alors reçu des réponses du serveur. Le test confirme que la machine cliente pouvait joindre le serveur après cette modification du pare-feu, mais ne suffit pas à démontrer à lui seul que l'attribution DHCP a été vérifiée sur tous les VLAN.

6. Bilan du compte rendu

  • Adresse IP statique configurée sur un serveur Windows.
  • Nom de l'hôte modifié en SRV.
  • Rôle serveur DHCP installé avec PowerShell.
  • Service DHCP démarré et vérifié à l'état Running.
  • Étendue CURLING créée et consultée.
  • Test de connectivité réussi après adaptation du pare-feu.
